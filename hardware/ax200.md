# Intel AX200 5GHz 热点（hostapd AP 模式）

AX200 开 5G 热点的完整记录。涉及驱动补丁、监管域、OpenRC 服务、DHCP 网段隔离。

## 1. 根因：为什么默认起不来

AX200 是 **self-managed 监管**（`iw reg get` 显示 `phy#0 (self-managed)`），监管域由驱动从 NVM 解析、**不走内核 regulatory.db**。固件里国家码焊死 `00`，全 5G 信道（ch36-165）挂 NO-IR（`IEEE80211_CHAN_NO_IR` / `NL80211_RRF_NO_IR`），hostapd 起 AP 被内核直接拒绝：

```
Frequency 5745 (primary) not allowed for AP mode, flags: 0x20853 NO-IR
```

NO-IR 是**驱动源码里加的**（`iwl-nvm-parse.c`），不是固件硬锁，但软件路径改不了固件的国家码。

## 2. 失败的尝试（别重复踩）

| 尝试 | 结果 |
|---|---|
| `iw reg set CN` | 无效，self-managed 不走 regulatory.db |
| 驱动补丁去掉 NO-IR（`iwl-nvm-parse.c` 两处） | 固件断言 `0x200014FC` 崩掉 |
| RibomBalt `ACTIVE\|IBSS` 强制 | 断言照样出，无用 |
| 降固件版本 | `IWL_22000_UCODE_API_MIN=MAX=77`，API 封死降不了 |
| 扫描注入国家码 | 无效，固件国家码不更新 |

## 3. 解决方案：MCC 注入

**强制固件国家码 CN**（`MCC_SOURCE_BIOS=2`），让固件认为 BIOS 报了 CN，信道可用。

### 3.1 驱动源码补丁（4 文件）

对 `drivers/net/wireless/intel/iwlwifi/`：

- `iwl-nvm-parse.c` — NVM 解析时注入 MCC
- `mvm/mvm.h` — 结构体声明
- `mvm/nvm.c` — MCC 注入点
- `mvm/ops.c` — 初始化挂钩

补丁源码在独立仓库 `ax200-5g-ap`（patch + README + 配置样例）。

### 3.2 iwlmvm 模块参数（触发）

`/etc/modprobe.d/iwlwifi-mcc.conf`：

```
options iwlmvm lar_country_code=CN lar_mcc_source=2 disable_lar=true
```

### 3.3 编译与安装

运行内核是 `7.2.7-gentoo-dist-bin`，源码树在 `/usr/src/linux-7.2.7-gentoo`（本地版本 `7.2.7-gentoo`，直接编 vermagic 不匹配）。做法：out-of-tree 热替换——把 iwlwifi 源码复制到工作目录，打补丁，用 dist-bin 构建树编译：

```bash
make -C /lib/modules/$(uname -r)/build M=<工作目录> modules
```

**先备份原 .ko**，替换后 `modprobe -r iwlmvm iwlwifi` + 重载。验证：

```bash
iw reg get    # 应显示 country CN
```

固件零修改（不写 EEPROM/OTP），重启不砖。

## 4. iwd 防抢卡

AX200 默认被 iwd 接管注册管理帧过滤（`cfg80211_mlme_register_action` 返回 `-EALREADY`），hostapd 设模式报：

```
nl80211: kernel reports: Match already configured
nl80211: Could not configure driver mode
```

`/etc/conf.d/iwd`：

```bash
command_args="-I wlan_ap"
```

用 `-I`（按接口名忽略）不用 `-P phy0`（phy 索引会漂，wlan_ap 有 udev 按 MAC 固定）。

**坑**：iwd 的 pidfile 可能过时（stale），`rc-service iwd stop` 杀不掉真进程。正解 `sudo pkill -x iwd` 后 `rc-service iwd start`。

## 5. udev 固定接口名

`/etc/udev/rules.d/70-persistent-net.rules`：

```
# AX200
ACTION=="add", SUBSYSTEM=="net", ATTR{address}=="88:f4:da:XX:XX:XX", NAME="wlan_ap"
# 树莓派直连
ACTION=="add", SUBSYSTEM=="net", ATTR{address}=="8c:32:23:XX:XX:XX", NAME="net_rpi"
```

接口名固定后 iwd 的 `-I wlan_ap` 才有效（否则 udev 改名前后名字对不上，iwd 匹配失效）。

## 6. hostapd 配置

`/etc/hostapd/wlan_ap.conf`：

```ini
interface=wlan_ap
driver=nl80211
ssid=your_ssid
hw_mode=a
channel=149
ieee80211n=1
ieee80211ac=1
ht_capab=[HT40+][SHORT-GI-20][SHORT-GI-40]
vht_capab=[SHORT-GI-80][RXLDPC][TX-STBC-2BY1]
vht_oper_chwidth=1
vht_oper_centr_freq_seg0_idx=155
wpa=2
wpa_key_mgmt=WPA-PSK
rsn_pairwise=CCMP
wpa_passphrase=...
```

### 关键参数

| 参数 | 作用 | 坑 |
|---|---|---|
| `channel` | 主信道（20MHz） | 选 ch149（UNII-3，33dBm，无 DFS） |
| `vht_oper_chwidth=1` | 80MHz 带宽 | 必须和 seg0 配对 |
| `vht_oper_centr_freq_seg0_idx` | 80MHz 中心信道 | **必须 = 主信道 ±2 或 ±6**，否则报 `Wrong coupling between HT and VHT/HE channel setting` |
| `vht_capab` | VHT 能力 | **别删**！删了掉到 300Mbps（协商 NSS 不稳） |
| `ht_capab` | HT 能力 | **不能删**（删了 `Could not determine operating frequency`），但 `[HT40+]` 是次信道方向必须有 |

### 中心信道速查

```
主 149 → 中心 155（149+6）
主 36  → 中心 42（36+6）
主 44  → 中心 42（44-2）
主 157 → 中心 155（157-2）
```

### 坑：ch36 起不来

ch36（5180MHz）有邻居 beacon，hostapd HT_SCAN 阶段想 swap 主次信道失败：

```
Switch own primary and secondary channel ...
Failed to set beacon parameters
```

ch149 干净，实测可用。

## 7. OpenRC 服务（hotspot）

`/etc/init.d/hotspot`：

```bash
#!/sbin/openrc-run
name="hotspot"
description="Intel AX200 5G AP for streaming"
supervisor=supervise-daemon
command="/usr/sbin/hostapd"
command_args="/etc/hostapd/wlan_ap.conf"
respawn_delay=3
respawn_max=10
respawn_period=300
output_log="/var/log/hotspot.log"
error_log="/var/log/hotspot.log"
depend() {
    need localmount
    before dnsmasq
    after udev
    use modules
}
start_pre() {
    local i
    for i in $(seq 1 45); do
        [ -d /sys/class/net/wlan_ap ] && break
        sleep 1
    done
    if [ ! -d /sys/class/net/wlan_ap ]; then
        eerror "wlan_ap not found"
        return 1
    fi
    ip link set wlan_ap down 2>/dev/null || true
    ip addr flush dev wlan_ap 2>/dev/null || true
    ip addr add 192.168.50.1/24 dev wlan_ap
    ip link set wlan_ap up
}
stop_post() {
    ip addr flush dev wlan_ap 2>/dev/null || true
}
```

### 启动顺序

```
udev（改名）→ net → hotspot（start_pre 配 IP）→ dnsmasq
```

- `before dnsmasq`：**软顺序**，dnsmasq 起来时 wlan_ap 已有 IP；hotspot 失败不拖死 dnsmasq（net_rpi 的 DHCP 照常）
- `after udev`：等 udev 改名完成，iwd 的 `-I wlan_ap` 才有效
- `start_pre`：等 wlan_ap 出现（最长 45s）→ 设 IP → up

**别写 `after dnsmasq`**（方向反了，dnsmasq 会先起、wlan_ap 不存在、报 `unknown interface wlan_ap`）。

**start_post 不要**：依赖已保证顺序，`rc-service dnsmasq restart` + `|| true` 只是掩盖错误。

## 8. dnsmasq 网段隔离

两个网段同进程：`net_rpi` 192.168.10.x（router 192.168.10.1）、`wlan_ap` 192.168.50.x（router 192.168.50.1）。

**坑**：`dhcp-option` 是全局的，不打 tag 会被后一条覆盖。曾导致有线拿到 `router=192.168.50.1`，Surface 路由表出现 `192.168.50.1 dev 有线 scope link` 的错误路由。

正确写法：

```
interface=net_rpi
bind-interfaces
dhcp-range=set:wired,192.168.10.50,192.168.10.150,12h
dhcp-option=tag:wired,option:router,192.168.10.1
dhcp-option=tag:wired,option:dns-server,223.5.5.5,114.114.114.114

interface=wlan_ap
dhcp-range=set:wifi,192.168.50.2,192.168.50.64,12h
dhcp-option=tag:wifi,option:router,192.168.50.1
```

`dhcp-range=set:tag名,...` 给 range 打 tag，`dhcp-option=tag:名,...` 只在该 range 生效。

**改完客户端要重新 DHCP**（`rc-service net.<有线> restart` 或 `dhcpcd -n`），否则旧租约里的错误网关还在。

## 9. dhcpcd 排除

`/etc/dhcpcd.conf`：

```
denyinterfaces wlan_ap
```

不让 dhcpcd 在 AP 接口跑 DHCP，否则双 IP / APIPA 169.254 问题。

## 10. 性能

- **iperf3 Surface→PC 稳定 516Mbps**
- PHY 协商 866Mbps（80MHz 2x2 MCS9 SGI），TCP ≈ PHY × 60%（802.11 半双工 MAC 开销：ACK、前导码、SIFS、退避）
- 10 秒零抖动，ch149 干净无干扰（对比 ch149 有 3 邻居时掉到 300）

想再高只能 160MHz（国内 5GHz 凑不出，要 6GHz/6E）。对串流（4K 50-100Mbps）500Mbps 远远够用。

**别信"千兆跑满"**：那是 USB-C 有线（943Mbps），有线千兆没有无线 MAC 开销，到 940+；WiFi 到不了是物理规律。

## 11. 排查命令备忘

```bash
# 确认接口名与 MAC
iw dev
cat /sys/class/net/wlan_ap/address    # 应为 88:f4:da:XX:XX:XX

# 确认 AP 状态（80MHz/center1=5775）
iw dev wlan_ap info

# 确认协商速率（看 tx/rx bitrate，判断是否掉档）
iw dev wlan_ap station dump

# 确认 iwd 没抢卡
pgrep -a iwd    # 应带 -I wlan_ap
iw dev wlan_ap link    # 应 Not connected

# 确认 dnsmasq 绑定
ss -ulpn | grep 67

# hostapd 日志
tail -f /var/log/hotspot.log

# 常见错误对照
# Match already configured              → iwd 抢卡（pkill iwd 重启）
# Wrong coupling ...                     → seg0 与主信道不匹配
# unknown interface wlan_ap              → dnsmasq 起太早（before dnsmasq 没生效）
# Could not determine operating frequency → ht_capab 被删了
# Failed to set beacon parameters        → 信道有邻居干扰（换 ch149）
```

## 12. 性能调优备忘

- 删 `vht_capab` → 掉到 300（协商 NSS 不稳），必须保留
- `ht_capab` 删了起不来（`HT40+` 是次信道方向），但可以补全（加 `[LDPC][TX-STBC]`）
- 多流 `-P 4`/`-P 8` 不提升总带宽（单流已到 PHY 上限）
- 信道干扰看 `iw dev wlan_ap scan`（邻居 AP 在 149 会压 TX）
- `iw dev wlan_ap station dump` 看 `tx bitrate`：稳定在 80MHz 双流 = 健康；掉 40MHz/单流 = 干扰
